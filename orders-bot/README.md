# Бот приёма заказов

Telegram-бот: клиенты оформляют заказы на отчёты, презентации, рефераты и т.п., исполнитель назначает цену, клиент вносит предоплату, переписка идёт через бота.

**Стек:** Python 3.11 · aiogram 3 · SQLAlchemy 2 (async) + SQLite · Alembic · Redis (FSM) · Docker Compose.

## Как это устроено

**Клиент** (личка с ботом, меню снизу):
`📝 Новый заказ` · `📦 Мои заказы` · `❓ Как это работает` · `🎁 Пригласить друга` · `💬 Поддержка`

1. Анкета: тип → тема → объём → срок → описание → файлы → подтверждение.
2. Ждёт цену. Ориентировочную оценку видит **только исполнитель**.
3. Получает цену с кнопками `✅ Согласен` / `💬 Обсудить` / `❌ Отказаться`.
4. Переводит по номеру телефона → `✅ Я оплатил` → отправляет скриншот чека.
5. Получает работу → `🏁 Принять работу`.

Всё, что клиент пишет в чат, пересылается исполнителю.

**Исполнитель** — приватная супергруппа с темами:
- на каждый заказ создаётся тема `🆕 #17 · Презентация · Имя`; эмодзи в названии меняется вместе со статусом;
- вверху темы закреплена карточка заказа: детали, оценка по прайсу, скидка клиента, оплаты и кнопки действий;
- ваши сообщения в теме бот пересылает клиенту; если отправить файл до полной оплаты, бот сначала попросит подтверждение;
- для вопросов без заказа у каждого клиента есть тема «поддержка»;
- команды `/orders` (активные заказы со ссылками на темы) и `/stats`.

**Статусы:** 🆕 Новый → 💬 Ждёт согласия → 💳 Ждёт предоплату → 🔎 Проверка → 🛠 В работе → 💳 Ждёт остаток → 🔎 Проверка → 💰 Оплачен → 📎 Сдан → ✅ Выполнен (или ❌ Отменён).

## Правила (меняются в коде)

| Что | Где | По умолчанию |
|---|---|---|
| Прайс, коэффициенты срочности | `bot/services/pricing.py` | заглушки — поправьте |
| Предоплата | `bot/services/money.py` | новый 50%, постоянный 25%, итог < 1 000 ₽ → 100% |
| Рефералы | `bot/services/money.py` | 1 друг → 10%, 2 → 15%, 4 → 20%; друг засчитывается после выполненного заказа от 500 ₽; приглашённому 5% на первый заказ; скидки не суммируются |
| Тексты | `bot/texts.py` | — |

## Настройка

1. **Бот.** В [@BotFather](https://t.me/BotFather) выполните `/newbot` и получите токен.
2. **Группа исполнителя.**
   - Создайте приватную группу и включите в её настройках **Темы** (Topics).
   - Добавьте бота и сделайте его **администратором** с правами «Управление темами» и «Закрепление сообщений». Бот-админ получает все сообщения группы.
3. **Конфиг:** `cp .env.example .env` и заполните `BOT_TOKEN` и реквизиты.
4. **ID.** Запустите бота (см. ниже) с временными `ADMIN_ID=0`:
   - напишите боту в личку `/id` → `user_id` запишите в `ADMIN_ID`;
   - в группе отправьте `/id@имя_бота` → `chat_id` (начинается с `-100`) запишите в `ADMIN_GROUP_ID`;
   - перезапустите бота.

## Локальный запуск

```bash
python3.11 -m venv .venv
./.venv/bin/pip install -r requirements-dev.txt
./.venv/bin/alembic upgrade head
./.venv/bin/python -m bot
```

Без `REDIS_URL` незаконченные анкеты хранятся в памяти и теряются при перезапуске. Заказы при этом сохраняются в любом случае.

## Деплой на VPS

```bash
git clone <repo> orders-bot && cd orders-bot
cp .env.example .env && nano .env
docker compose up -d --build
docker compose logs -f bot
```

- Миграции применяются автоматически при старте контейнера.
- БД лежит в volume `bot-data`. Бэкап:
  `docker compose cp bot:/app/data/bot.db ./backup-$(date +%F).db`
- Обновление: `git pull && docker compose up -d --build`.

### Telegram недоступен с сервера
Некоторые хостинги режут часть IP Telegram. Бот тогда падает с `TelegramNetworkError: Request timeout error`. В `docker-compose.yml` для этого закреплён рабочий адрес (`extra_hosts`). Если он тоже перестал отвечать, найдите другой:
```bash
for ip in 149.154.167.220 149.154.167.99 149.154.166.110 149.154.175.100 91.108.56.100; do
  printf "%-16s " "$ip"
  curl -4 -s -m 8 --resolve api.telegram.org:443:$ip -o /dev/null -w "%{http_code}\n" \
    https://api.telegram.org/ || echo "нет"
done
```
Подойдёт адрес, который ответил `302`. Впишите его в `extra_hosts` и выполните `docker compose up -d`. Надёжнее всего разместить бота на VPS за рубежом.

## Структура

```
bot/
  __main__.py        запуск, диспетчер, middleware
  config.py          настройки из .env
  texts.py, views.py строки и рендер карточек
  callbacks.py, states.py, filters.py, middlewares.py
  keyboards/         reply-меню и inline-кнопки
  handlers/          common, order_form, client_orders, admin, relay, service, errors
  services/          pricing, money, order_flow (статусы), clients, topics, notify
  db/                models, repo (атомарные переходы), session
alembic/             миграции
tests/
```

## Безопасность

- Токен и реквизиты хранятся только в `.env`, файл в `.gitignore`.
- Пользовательский ввод экранируется в HTML.
- Переходы статусов выполняются условным `UPDATE`, поэтому двойные нажатия и устаревшие кнопки ничего не ломают.
- ⚠️ Если регулярно принимаете переводы на карту, оформите самозанятость (НПД): банки блокируют «коммерческие» переводы на личные счета.
